# Test script: version 0.1.1

Corrections after the first test of 0.1.0. Same test account and library copy as before ([v0.1.0.md](v0.1.0.md)).

1. In the test account, open Mulu 0.1.0 once and note how many files it shows, then close it. Download `Mulu_0.1.1_x64-setup.exe` from https://github.com/miguelbconde/mulu/releases/tag/v0.1.1 and install it **over** 0.1.0, without uninstalling. Note any warning.
2. Mulu opens with the same library, already read: it must **not** read everything again. The bottom shows **Version 0.1.1**.
3. **Show in folder:** search for a word, click **Show in folder** on a result in a subfolder with spaces in its name. Explorer must open that folder with the file selected.
4. **Closing dialogs:** open the list of files that could not be read: it is grouped by reason, with the counts at the top. Close it with the **×** at the top; open it again and close it with **Esc**. Same for the help (**?**).
5. **Report:** in that list, click **Copy a reading report for the developer** and paste it in your message (Ctrl+V). It contains only names, sizes and times.
6. **Speed:** to measure the new reading speed, the library must be read again. Uninstall Mulu (**Settings → Apps → Mulu → Uninstall**) and, in the uninstaller, tick **Delete the application data** (this deletes only Mulu's index, never your books). Install 0.1.1 again, choose the same folder, and time the reading from start to end. Note whether the computer felt slow. Then copy the report again and send it.
